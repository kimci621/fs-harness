# Уровни сложности задач: выжимка для роутера

Роутер fsh (`src/tier.js`) перед запуском агента на задаче Jira спрашивает jev, какого она уровня,
и берёт агентов из `tiers.map` конфига. Критерии ниже — выжимка из трёх документов с примерами:
[easy.md](easy.md), [medium.md](medium.md), [hard.md](hard.md).

| Уровень | План и читающие действия (analyze) | Исполнитель | Фолбэк на рейт-лимит |
| --- | --- | --- | --- |
| easy | `sonnet-low` | `sonnet-low` | `agy-low` |
| medium | `sonnet-xhigh` | `sonnet-xhigh` | `agy-high` |
| hard | `opus` (xhigh) | `opus-high` | `agy-high` |

- **easy** — место и ответ уже названы: стиль, текст, удалить лишнее, merge без конфликтов, поля Jira.
  Чужой код читать и выбирать решение не нужно, оплаты и аналитика не упоминаются.
- **medium** — обычная фича или баг с понятной причиной: повторить существующий паттерн, починить
  тесты, треды ревью, конфиг, конфликт вне оплат.
- **hard** — всё про оплату и чекаут (способы оплаты, рассрочка, тарифы, суммы, payload, шлюзы,
  контракт с бэком), а также баг без названной причины, миграции, аудит эпика, новая подсистема,
  проверка плана или гипотез, безопасность.

## Когда роутер не срабатывает

- Агент задан флагом `--agent` (или `agent` в MCP) — роутер молчит.
- `tiers.enabled: false` или у роли `task-tier` нет профиля в `classify.roles` — выключен.
- jev упал или не ответил за `classify.timeoutMs` — остаётся прежний выбор (`agent` из конфига).
- jev ответил с p ниже `classify.minP` — уровень `tiers.uncertain` (по умолчанию `medium`).

## Откуда цифры

472 уникальных промпта из истории Claude Code (fitstars-frontend, FS-Harness, 25.09.2026),
разметка вручную субагентами: 168 easy, 243 medium, 61 hard. Проверка критериев jev на 120
случайных промптах: при p ≥ 0.8 ответил на 52, совпал с разметкой в 83%, недооценил 5.
Недооценка дороже переоценки, поэтому неуверенный ответ уходит в medium, а не в easy.

Правишь критерий в `src/tier.js` — прогони ту же сверку и обнови примеры здесь.
