# fsh — спецификация

Дата: 2026-08-14. Статус: утверждено пользователем (a.latipov).

## Задача

CLI-обёртка над `glab` для повседневной работы с MR в GitLab. Не привязана к конкретному GitLab-инстансу: repo/host настраиваются. Должна одинаково хорошо работать из терминала человека и из AI-агентов (детерминированный вывод, флаг `--json`, понятные ошибки).

## Нефункциональные требования

- Node.js ESM, **ноль npm-зависимостей**. Единственные внешние бинари: `glab`, `git`, `node`.
- Все данные — через `glab api` (JSON), никакого парсинга человекочитаемого вывода `glab` (кроме команды создания worktree — это `git`).
- Команды ждут асинхронные операции (пайплайны, джобы) с анимацией: спиннер + живой статус джоб, опрос каждые 5 секунд.
- Ошибки — понятные сообщения с подсказкой «что сделать», exit code ≠ 0.
- Конфиг: `~/.config/gl-helper/config.json`. Приоритет: флаг CLI > env (`GL_HELPER_REPO`, `GL_HELPER_HOST`) > конфиг. Без настроенных repo/host glab-команды падают с подсказкой `config init`.

## Команды

| Команда | Описание |
|---|---|
| `mrs` | Все открытые MR: iid, title (+Draft), `source→target`, статус head-пайплайна, комментарии (всего / открытых тредов / решённых), конфликт есть/нет |
| `mr <ветка\|номер>` | Один MR в том же формате. Поиск по части имени ветки (неточное, case-insensitive) среди открытых MR; также принимает `!2547` и `2547` |
| `conflict <mr\|ветка> [--agent claude\|pi]` | Решить конфликт силами агента (см. ниже) |
| `jobs <mr\|ветка>` | Джобы последнего MR-пайплайна: stage, имя, статус, id |
| `run <джоба> <mr\|ветка>` | Запустить manual-джобу по имени (или id) в последнем MR-пайплайне |
| `deploy <ветка\|mr> [N]` | build → ждать успеха → запустить `deploy_dev` (или `deploy_dev2…10`) → ждать итога |
| `config init` / `config show` | Создать/показать `~/.config/gl-helper/config.json` |
| `help` | Список команд с примерами |

Флаги: `-R/--repo`, `--json` (read-команды), `--agent` (conflict), `-B/--build-job` (deploy, дефолт `build_image`).

## Конфликт: цепочка

1. Резолв MR, `git fetch origin <source> <target>` в `projectDir` из конфига.
2. `git merge-tree --write-tree --name-only --no-messages origin/<target> origin/<source>`: exit 1 → конфликт, exit 0 → чисто. Первая строка stdout — OID дерева, отбрасывается; остальные строки — конфликтующие файлы. Нет конфликта → сообщить и выйти. Поле `has_conflicts` из GitLab не используется: при `unchecked` оно врёт.
3. Временный worktree: `$projectDir/.worktrees/gl-helper-<iid>-<ts>` (detached от `origin/<source>`), внутри — ветка `gl-helper/<iid>-<ts>`.
4. Агент (claude или pi, headless `-p`) работает **только внутри worktree**, cwd = worktree. Промпт (утверждён):
   - данные MR: номер, URL, ветки `source→target`, worktree уже готов, список конфликтующих файлов;
   - шаги: `git merge origin/<target>`, решить конфликты вручную, сохраняя функциональность обеих веток (приоритет равный), запрещены «взять всё ours/theirs» и force-push;
   - верификация: линт и unit-тесты проекта перед коммитом;
   - коммит по правилам проекта (посмотреть `git log` и повторить стиль);
   - push: `git push origin HEAD:<source>` — обновляет MR, target не трогать;
   - конфликтов нет — просто сообщить, ничего не коммитить.
5. После агента: проверка, что HEAD ушёл вперёд `origin/<source>` (иначе — предупреждение и выход с ошибкой).
6. Пайплайн build жмёт **fsh**, не агент: если head-пайплайн MR устарел (sha ≠ нового HEAD) — создать новый MR-пайплайн, найти build-джобу, запустить, дождаться, показать статус.
7. **Гарантированная очистка** (finally): `git worktree remove --force` + `git worktree prune` + удаление временной ветки.

## Архитектура

```
src/
  main.js        — разбор argv, dispatch, help
  glab.js        — обёртка glab api (все вызовы), exec инжектируется (тесты)
  resolve.js     — поиск MR по номеру/части ветки → объект MR
  config.js      — чтение/запись ~/.config/gl-helper/config.json
  ui.js          — спиннер, прогресс, перерисовка статусов, humanize времени
  format.js      — таблицы и строки вывода (текст/JSON)
  commands/      — по файлу на команду (mrs, mr, jobs, run, deploy, conflict, config)
test/            — node --test, мокнутый exec: парсинг/логика без сети
```
