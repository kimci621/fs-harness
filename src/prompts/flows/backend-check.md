# Сценарий: подтвердить контракт бэкенда и тестовые данные

Если у проекта настроен бэкенд, контракт API и тестовые данные подтверждаются по коду репозитория бэкенда, а не по описанию задачи.

Проверить настройки активного проекта и путь к бэкенду:

```
fsh config show
```

Если бэкенд не настроен (поле `backend` пусто), контракт подтвердить локально нельзя.

## 1. Подтвердить контракт API

Код бэкенда находится в каталоге `backend.dir` (репозиторий `backend.repo`, целевая ветка `dev`).

Перед началом прочитай `AGENTS.md` в каталоге бэкенда.

Схема поиска контракта:
1. **Роут**: найди объявление эндпоинта в каталоге `routes/` (например, `routes/api.php` или вложенных файлах).
2. **Контроллер**: открой метод контроллера, на который указывает роут.
3. **Request/Resource**:
   - Входные параметры и валидация: смотри FormRequest (`app/Http/Requests/...`), метод `rules()`.
   - Выходные данные и структура ответа: смотри Resource (`app/Http/Resources/...`), метод `toArray()`.
4. **Фиксация**:
   - Каждый факт контракта фиксируй со ссылкой `файл:строка` (например, `app/Http/Resources/UserResource.php:42`).
   - Scribe (`public/docs/openapi.yaml`) используй только как оглавление; источник правды - исключительно PHP-код.
   - Любое расхождение описания задачи с реальным кодом бэкенда называй вслух в чате или отчёте.

## 2. Тестовые данные

Для воспроизведения сценариев или подготовки тестовых данных используй фабрики и tinker бэкенда:

1. **Фабрики**: модели и генераторы тестовых данных находятся в `database/factories/`.
2. **Tinker**: консоль запускается из каталога бэкенда скриптом:
   ```bash
   ./artisan-tunnel-dev6.sh tinker
   ```
3. **Безопасность базы данных**:
   - По умолчанию работай строго в режиме **ТОЛЬКО ЧТЕНИЕ**.
   - Любая запись, создание или изменение записей в БД - **ТОЛЬКО с явного подтверждения человека**.
