# Сценарий: взять задачу в работу

Человек сказал «возьми FD-XXXX в работу». Дальше по шагам; каждый шаг делает `fsh`, решения
принимаешь ты.

## 1. Прочитать задачу

```
fsh jira FD-XXXX
```

Описание, статус, исполнитель и комментарии. Комментарии читай до конца: там чаще всего лежит
уточнение, которое отменяет половину описания. Не понял, что просят, — спроси человека, а не
догадывайся.

## 2. Встать на ветку

```
fsh task start FD-XXXX
```

Ветка `feature/FD-XXXX` создаётся от целевой ветки проекта или, если уже есть, берётся как есть.
Статус задачи в Jira команда не двигает: переход с обязательными полями умеет скилл проекта
`jira-transitions`.

Ошибка `dirty_checkout` означает незакоммиченные правки в рабочем дереве. Не коммить и не прятать
их сам — это чужая работа. Покажи список человеку и жди решения.

## 3. Разобраться в коде

Читай проект обычными инструментами. Если у проекта настроен backend (`fsh config show`), контракт подтверждай в нём по flows/backend-check.md.

Если задача большая и непонятно, куда смотреть:

```
fsh analyze FD-XXXX
```

Это отдельный агент, который читает проект под задачу и пишет разбор. Он стоит денег и времени,
поэтому только когда сам не находишь концов.

## 4. Показать план и дождаться утверждения

План — это список правок: какие файлы, что в них меняется, чего решено не трогать. Пиши его в чат,
коротко. **Код до утверждения не пишешь.** Человек может переписать половину плана, и тогда вся
написанная работа уйдёт в мусор.

## 5. Реализовать

Правила проекта живут в его `CLAUDE.md` и скиллах — они главнее твоих привычек. Соседний код,
форматирование и комментарии, к которым задача не просила прикасаться, не трогаешь.

Коммит:

```
fsh commit
```

Паттерн сообщения берётся из проекта. Файлы добавляются явными путями, `git add -A` запрещён.

## 6. Приёмка

```
fsh task judge FD-XXXX
```

Судья сверяет дифф ветки с текстом задачи. `reject` и `revise` — доделай названное и прогони ещё
раз. `approve` — скажи человеку, что задача готова, и напомни про обязательные поля Jira
(`fsh flow show fill-jira`).

## Чего на этом сценарии не делаешь

- Не пушишь и не открываешь MR. Это отдельный сценарий и отдельная команда человека.
- Не двигаешь статус задачи в Jira.
- Не расширяешь объём работы: нашёл соседнюю проблему — скажи о ней, не чини молча.
