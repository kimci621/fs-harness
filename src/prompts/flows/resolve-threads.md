# Сценарий: разобрать тред ревью

Человек принёс замечание ревьюера («посмотри тред», «ревьюер спрашивает…», «разбери треды»).
Треды закрываются ответом в двух местах: в треде MR и в треде задачи в Mattermost. Обе реплики
пишутся только после пуша, иначе ревьюер откроет дифф и фикса там не увидит.

## 1. Прочитать открытые треды

```
fsh mr-comments <mr|ветка> --open
```

В выводе у треда стоит префикс id из 8 символов, полный id нужен для ответа (шаг 5).

## 2. Проверить замечание по коду

Замечание — это гипотеза, а не факт. Пройди путь, о котором говорит ревьюер, по коду. Не
подтвердилось — не правь, а объясни в ответе, почему сочетание невозможно.

## 3. Поправить и закоммитить

Правка, тест на сценарий из замечания, прогон затронутых тестов. Коммитишь только свои пути
(`git add <файлы>`, не `-A`), затем `fsh commit -y`.

Разбирать треды можно и автоматом: `fsh threads <mr> -y`. После approve судьи ран может
остаться в `pending_approval` без пуша — сверь `fsh runs` и доопубликуй `fsh publish <runId> -y`.

## 4. Запушить

```
fsh task push
```

Без пуша к шагам 5 и 6 не переходишь.

## 5. Ответить в треде MR

Полный id треда:

```
glab api "projects/:id/merge_requests/<iid>/discussions?per_page=100" \
  | python3 -c "import json,sys; [print(d['id']) for d in json.load(sys.stdin) if d['id'].startswith('<префикс>')]"
```

Ответ:

```
glab api -X POST "projects/:id/merge_requests/<iid>/discussions/<id>/notes" -f body="<текст>"
```

В тексте: подтвердилось ли замечание, хэш коммита с фиксом, что поменялось и какие тесты его
держат. Тред не резолвишь: решает ревьюер. Если человек попросил резолвить — только
`glab api -X PUT ".../discussions/<id>?resolved=true"`, флаг `--field` молча не срабатывает.

## 6. Ответить в треде задачи в Mattermost

Корень треда — сообщение `fsh mm review` в канале сценария `review`. Команда находит его по ключу:

```
fsh mm reply FD-XXXX "<текст>" --dry-run   # покажет тред и текст
fsh mm reply FD-XXXX "<текст>"
```

`not_found` — задачу в канал ещё не отписывали: сначала `fsh mm review FD-XXXX`, и то только
если задача правда уехала в ревью. `fsh mm post` для этого не годится, он пишет в канал отдельным
постом.

Текст — одна-две фразы: какое замечание поправлено, в каком MR и коммите, что ветка запушена.
Деталей из треда MR не повторяй.

## 7. Отдать результат

Человеку: что подтвердилось, хэш коммита, где оставлены ответы.

## Чего на этом сценарии не делаешь

- Не отвечаешь в треды до пуша.
- Не резолвишь чужие треды без просьбы.
- Не делаешь `push --force` и не переписываешь историю.
