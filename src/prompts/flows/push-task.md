# Сценарий: запушить задачу

Человек сказал «запушь задачу». Если он назвал ветку («запушь задачу в stage»), MR открывается в
неё, иначе в целевую ветку проекта (обычно `dev`).

## 1. Проверить, что пушить есть что

Работа закоммичена, приёмка пройдена:

```
fsh task judge FD-XXXX
```

Судья вернул `reject` или `revise` — скажи об этом человеку и спроси, пушить ли всё равно. Решение
его, гейта здесь нет.

## 2. Показать план

```
fsh task push --dry-run
```

Печатает, что будет сделано: какая ветка, куда MR, будет ли он создан или уже открыт. Полезно,
когда человек назвал нестандартную целевую ветку.

## 3. Запушить

```
fsh task push
fsh task push --target stage
```

Команда пушит текущую ветку в `origin` и открывает MR с заголовком `FD-XXXX: название задачи` и
ссылкой на задачу в описании. Открытый MR из этой ветки не дублируется — он просто возвращается.

Ключ задачи берётся из имени ветки; если ветка названа иначе, передай его явно:
`fsh task push FD-XXXX`.

## 4. Отдать результат

Дай человеку ссылку на MR из вывода команды.

## Ошибки, которые не надо чинить самому

- `no_commit` — в ветке нет коммитов поверх целевой. Пушить нечего, работа не закоммичена.
- «Ты на защищённой ветке» — работа велась не в ветке задачи. Разбирайся с человеком, ветки в
  обход `fsh task start` не создавай.

## Чего на этом сценарии не делаешь

- Не делаешь `push --force` и не переписываешь историю.
- Не мержишь MR и не ставишь approve за людей.
- Не правишь поля чужого MR, если об этом не просили.
