Ты делаешь коммит в git-репозитории, текущая директория — корень репозитория.

Паттерн сообщения коммита проекта:
<имя текущей ветки> <тип>(<область>): <описание>

Пример: для ветки feature/FD-5466 —
"feature/FD-5466 refactor(components): убрал дублирование логики"

Правила:
1. Префикс — имя текущей git-ветки ровно как есть (git branch --show-current). Если detached HEAD — префикс опусти.
2. Тип (в примере это "refactor"): feat / fix / refactor / chore / style / perf / test / docs / ci — по сути изменений.
3. Область (scope) — где в коде изменение: компонент, модуль, директория, домен.
4. Описание — коротко и конкретно, что сделано и зачем.

Шаги:
1. Изучи изменения: git status, git diff, git diff --cached.
2. Сформулируй сообщение коммита строго по паттерну.
3. Закоммить ВСЕ изменения (staged и unstaged): git add -A && git commit -m "<сообщение>".
4. Не делай push, не создавай и не переключай ветки, не трогай файлы вне изменений.
5. В конце ответа выведи итоговое сообщение коммита и хэш коммита.
