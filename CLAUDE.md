# CLAUDE.md — FS-Harness

## Что читать

- **[PLAN.md](PLAN.md) — спецификация проекта, а не черновик.** Решения в нём зафиксированы: архитектура,
  фазы, список «чего в v1 не делаем». Расходиться с ним можно, но только вслух и с правкой самого PLAN.md
  тем же коммитом.
- [AGENTS.md](AGENTS.md) — устройство того, что в репозитории есть сейчас.
- [docs/SPEC.md](docs/SPEC.md) — поведение нынешних команд.

Работа идёт фазами из PLAN.md. Промпт вида «делаем фазу N, дальше не идём» — это всё, что нужно:
границы фазы и критерий её закрытия описаны там же.

## Жёсткие ограничения

1. **Ноль новых внешних программ и сервисов.** `npm ci` и `fsh` — весь запуск. Ничего, что надо
   поставить, залогинить или поднять рядом с проектом. Полом системы остаются `claude`, `git`, `glab`,
   `security`; `pi` и LM Studio опциональны, их отсутствие не ломает дефолтную конфигурацию.
2. **npm-библиотеки, наоборот, берём охотно.** Есть готовое решение — тащим, а не переписываем.
   Пакеты добавляются в той фазе, где впервые нужны, не заранее.
3. **Тест-раннер встроенный** (`node --test`). Vitest и прочее сюда не едет.
4. **Никакого TypeScript и шага сборки.** `.js` с ESM, `bin/fsh.js` запускается как есть.

## Правила работы

- **Никогда `git add -A` и `git add .`** — только явные пути своих правок. Рабочее дерево бывает
  общим, чужой in-progress код в коммит попадать не должен.
- Каждый коммит — отдельный смысловой шаг. Не свалка.
- Комментарии в коде **на русском**, одна короткая строка и только там, где правда нужна.
- Не «улучшай» соседний код, форматирование и комментарии, к которым не просили прикасаться.
- Заметил постороннее мёртвое — скажи, не удаляй.

## Проверки

```bash
npm test                            # node --test, сеть не нужна
rm -rf node_modules && npm ci && npm test   # в конце каждой фазы
fsh doctor                          # самодиагностика окружения
```

Последняя строка второй команды — исполняемая проверка ограничения №1: если запуск с нуля требует
чего-то кроме `npm ci`, вылезет здесь.

## Границы
